# v0.3.0: Multi-Project Infrastructure

## Summary

Implement global project context with LRU-cached workspace instances, enabling agents to work across multiple C# projects in a single MCP session without requiring project path in startup args.

## Motivation

**Current limitation (v0.2.x):**
- Server requires project path at startup: `RoslynMcp.exe /path/to/project`
- Agents must restart server to switch projects
- MCP configuration is project-specific, not global

**Desired state (v0.3.0):**
- Server starts globally: `RoslynMcp.exe`
- All 24 tools accept optional `projectPath` parameter
- Workspace instances cached with LRU eviction
- Agents can work on multiple projects in one session

## Goals

### 1. Multi-Workspace Support

**WorkspaceManager enhancements:**
- LRU cache of workspace instances (keyed by project path)
- Configurable cache size (default: 10 projects)
- Smart path resolution (relative paths, CWD, normalization)
- FileSystemWatcher per workspace for incremental updates
- Automatic eviction on cache pressure

**WorkspaceResolver facade:**
- Per-tool entry point to WorkspaceManager
- `TryGetCompilation(projectPath, ...)` with structured error handling
- `TryGetProject(projectPath, ...)` for metadata queries
- `GetSolution(projectPath)`, `GetRootPath(projectPath)` helpers
- `InvalidateFile(projectPath, filePath)` for external edits

### 2. Tool Migration

Migrate all 24 tools to use `WorkspaceResolver`:
- Add `projectPath` parameter (last position, optional, defaults to CWD)
- Replace direct WorkspaceManager calls with `TryGetCompilation`/`TryGetProject`
- Add `ProjectPathDescription` constant for consistent documentation
- Update tool descriptions to mention multi-project support

**Status (as of current session):**
- ✅ Infrastructure complete (WorkspaceManager, WorkspaceResolver)
- ✅ RoslynMcpTool base class with helper methods
- ✅ **ALL 24 tools migrated** (Phase 2 complete!)
- ⏳ Multi-project testing in progress (Phase 3a)

### 3. Path Resolution Strategy

**Smart resolution order:**
1. Explicit `projectPath` provided → use directly
2. `projectPath` is relative → resolve against CWD
3. `projectPath` is null → use CWD
4. `projectPath` is `.csproj` file → direct load
5. `projectPath` is directory → scan for `.csproj` → fallback to AdhocWorkspace

**Error handling:**
- Invalid path → structured error with hints
- Multiple `.csproj` in directory → error with list, ask user to disambiguate
- No `.csproj` found → AdhocWorkspace fallback (source-only mode)

### 4. Cache Management

**LRU eviction:**
- Default capacity: 10 workspaces
- Eviction on `Add()` when at capacity
- Least-recently-used workspace disposed + removed
- FileSystemWatchers disposed with workspace

**Invalidation:**
- File edits via tools → automatic invalidation
- External edits → FileSystemWatcher triggers reload
- Manual invalidation via `workspace.InvalidateFile()`

**Future enhancement (post-v0.3.0):**
- Configurable cache size via environment variable
- Memory pressure monitoring
- Diagnostics endpoint (`roslyn_get_cache_stats`)

## Breaking Changes

**MCP Configuration:**
```json
// v0.2.x (project-specific)
{
  "servers": {
    "roslyn": {
      "command": "/path/to/RoslynMcp.exe",
      "args": ["/path/to/MyProject"]
    }
  }
}

// v0.3.0 (global)
{
  "servers": {
    "roslyn": {
      "command": "/path/to/RoslynMcp.exe",
      "args": ["."]  // Optional: default workspace root
    }
  }
}
```

**Tool usage:**
```typescript
// v0.2.x — implicit project from startup args
roslyn_get_type_members({ typeName: "Foo" })

// v0.3.0 — explicit project per tool call
roslyn_get_type_members({ typeName: "Foo", projectPath: "./src/MyLib/MyLib.csproj" })
roslyn_get_type_members({ typeName: "Bar", projectPath: "./src/MyApp/MyApp.csproj" })
```

**Backward compatibility:**
- If startup arg provided, becomes default `projectPath` for tools
- Tools work without `projectPath` if single project in workspace

## Known Issues

### stdout Contamination (CRITICAL — BLOCKER for testing)

**Problem:** Server writes startup diagnostic messages to stdout, corrupting JSON-RPC protocol stream.

```bash
$ echo '{"jsonrpc":"2.0","id":1,"method":"initialize",...}' | RoslynMcp.exe .
Pre-loading 1 project(s)...
✓ Loaded: .
{"jsonrpc":"2.0","id":1,"result":{...}}  # Valid JSON-RPC response, but preceded by non-JSON text
```

**Impact:**
- MCP clients and test harnesses cannot parse responses
- All automated testing blocked
- Manual testing unaffected (clients may ignore stderr)

**Root Cause:** `Program.cs` writes directly to `Console.WriteLine` during workspace pre-loading.

**Fix:**
- Move all diagnostic output to stderr: `Console.Error.WriteLine`
- OR suppress entirely (FileLogger already captures this)
- OR make conditional on environment variable (e.g., `ROSLYNMCP_VERBOSE`)

**Priority:** HIGH — must fix before v0.3.0-alpha release.

---

### Cross-Project Semantics (HIGH Priority)

**Problem:** `Compilation` duplication when projects reference each other.

When `A.csproj` references `B.csproj` via `<ProjectReference>`, MSBuildWorkspace loads B into A's Solution as a full project node. If an agent later requests `B.csproj` directly, a second WorkspaceInstance is created → B's sources are parsed twice.

**Impact:**
1. Memory duplication (low-medium severity) — tolerable for now
2. **Cross-project semantic operations incomplete** (HIGH severity) — `roslyn_find_references`, `roslyn_preview_rename`, etc. operate on a Solution, not Compilation. Two separate WorkspaceInstances = two separate Solution graphs with no knowledge of each other. Silent incorrectness.

**Recommended fix (post-v0.3.0 merge):**
Solution-level caching via `.sln`/`.slnx` support. Use `OpenSolutionAsync()` as cache key instead of individual `.csproj` paths. One Solution per `.sln` file; all projects share the same graph; zero duplication; full cross-project semantics. (See ScratchPad.md for full analysis)

### Glob Patterns (Future Enhancement)

**Idea:** Allow file globbing in startup args: `src/**/*.csproj`
- Resolve globs at startup
- Cache all matched projects
- Provides upfront estimate of cache requirements
- Warn if project count exceeds threshold

**Status:** Deferred to post-v0.3.0
